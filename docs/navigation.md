## La coque à 5 entrées + Réglages existe
Le menu a 6 entrées (5 + Réglages) : Aujourd'hui, Opérations, Analyses, Budgets, Échéances, Réglages (en : Today, Transactions, Analysis, Budgets, Due dates, Settings). Les anciennes pages restent atteignables par l'onglet d'un écran (Analyses), par l'écran Échéances, par la page Réglages ou par la palette (règle testée, voir plus bas).

## Routes du dossier `(dashboard)` (toutes derrière la coque)
`/` (Aujourd'hui), `/transactions`, `/transactions/import`, `/analyses` (nouvelle, écran Analyses), `/evolution`, `/flux`, `/depassements` (anciennes adresses d'Analyses), `/budgets`, `/budgets/fixed`, `/echeances` (nouvelle, écran Échéances), `/calendar`, `/cashflow` (anciennes adresses d'Échéances), `/settings` (nouvelle, page Réglages), `/accounts`, `/categories`, `/tags`, `/smart-rules`, `/recurring`. Rattachement : voir « Entrée active ». Plus d'onglets de pages : `SectionTabs`, `TABS` et `ATTACHED_PAGES` sont supprimés de `nav-config.ts`. Échéances : un écran unique (courbe, calendrier, liste) sur `/echeances` ; `/calendar` et `/cashflow` ouvrent le même écran (chaque `page.tsx` affiche `EcheancesScreen`). Analyses : un écran à trois onglets internes (Répartition, Évolution, Dépassements), l'onglet est un état de l'écran, pas une adresse ; `/analyses` s'ouvre sur Répartition, `/flux` sur Répartition, `/evolution` sur Évolution, `/depassements` sur Dépassements (chaque `page.tsx` affiche `AnalysesScreen` avec `initialTab`). Page Réglages : liste Comptes, Catégories, Tags, Règles, Récurrences, chacun avec une ligne d'explication (espace `Settings`) et un lien. Aucune redirection (`redirect(`) dans ce dossier : les anciennes adresses affichent l'écran, elles ne renvoient pas vers `/analyses`. **Règle critique : aucune page ne devient inaccessible**, vérifiée par comparaison des `page.tsx` du dossier avec la table ; chaque page est atteinte par une entrée, la page Réglages, un onglet de l'écran Analyses (`/evolution`, `/flux`, `/depassements`) ou l'écran Échéances (`/calendar`, `/cashflow`), vérifié par le contenu de leur `page.tsx`. Source : `nav-config.ts`, `settings/page.tsx`, `analyses-screen.tsx`, `echeances-screen.tsx`. Testé : `nav-accessibility.test.ts`.

## Qui est authentifié
Le middleware s'applique à toutes les routes sauf `api`, fichiers statiques et fichiers avec extension : il gère la langue (next-intl) puis la session Supabase ; sans utilisateur connecté il redirige vers `/login`, avec utilisateur connecté `/login` renvoie vers `/`. Donc toutes les routes de la coque exigent une connexion. Source : `src/middleware.ts:8-28`, `shared/lib/supabase/middleware.ts:41-62`. Le layout enveloppe tout dans `BackendHealthGuard` (garde de disponibilité du back, non détaillé ici). Pas testé.

## Ce qu'on stocke
Rien de propre à la coque. Le thème est gardé par `next-themes` dans le navigateur (clé par défaut ; non vérifiée dans le code). Les visites guidées : voir `docs/tour.md`.
