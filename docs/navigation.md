## La coque à 5 entrées + Réglages existe
Le menu a 6 entrées (5 + Réglages) : Aujourd'hui, Opérations, Analyses, Budgets, Échéances, Réglages (en : Today, Transactions, Analysis, Budgets, Due dates, Settings). Toutes les pages restent atteignables par une entrée, la page Réglages, un onglet d'Analyses ou, sur mobile, « Plus » (règle testée, voir plus bas).

## Routes du dossier `(dashboard)` (toutes derrière la coque)
`/` (Aujourd'hui), `/transactions`, `/transactions/import`, `/analyses` (écran Analyses), `/budgets`, `/budgets/fixed`, `/echeances` (écran Échéances), `/settings` (page Réglages), `/accounts`, `/categories`, `/tags`, `/smart-rules`, `/recurring` : 13 pages. Rattachement : voir « Entrée active ». Plus d'onglets de pages : `SectionTabs`, `TABS` et `ATTACHED_PAGES` sont supprimés de `nav-config.ts`. Échéances : un écran unique (courbe, calendrier, liste) sur `/echeances`. Analyses : un écran à trois onglets internes (Répartition, Évolution, Dépassements), l'onglet est un état de l'écran, pas une adresse. Page Réglages : liste Comptes, Catégories, Tags, Règles, Récurrences, chacun avec une ligne d'explication (espace `Settings`) et un lien. **Anciennes adresses : `/evolution`, `/flux`, `/depassements`, `/calendar`, `/cashflow` (avec ou sans `/fr`, `/en`) n'existent plus** : leurs `page.tsx` sont supprimés, elles répondent 404 si on est connecté, `/login` sinon (middleware, `src/middleware.ts`) ; aucun `not-found.tsx` : page 404 par défaut de Next ; aucune redirection (ce fut un choix : spec refonte-mobile, CA8). Plus aucun lien, entrée, titre ni test du dépôt ne les cite comme pages. **Règle critique « aucune page existante ne devient inaccessible », reformulée** : chaque page du dossier `(dashboard)` doit avoir une ligne dans la table de rattachement du test (et inversement), et être atteinte par une entrée, la page Réglages ou une sous-page d'une entrée ; sur mobile, Budgets, Échéances et Réglages le sont par « Plus ». Les 5 écrans anciennement doublés restent atteignables par Analyses et Échéances. Source : `nav-config.ts`, `settings/page.tsx`, `more-menu.tsx`. Testé : `nav-accessibility.test.ts` (12 pages + `/settings`, anciennes adresses ni pages ni routes connues, avec ou sans langue).

## Qui est authentifié
Le middleware s'applique à toutes les routes sauf `api`, fichiers statiques et fichiers avec extension : il gère la langue (next-intl) puis la session Supabase ; sans utilisateur connecté il redirige vers `/login`, avec utilisateur connecté `/login` renvoie vers `/`. Donc toutes les routes de la coque exigent une connexion. Source : `src/middleware.ts:8-28`, `shared/lib/supabase/middleware.ts:41-62`. Les routes d'une page supprimée (les 5 anciennes adresses) passent aussi par ce middleware : connecté, 404 ; sinon `/login`. La Déconnexion de « Plus » appelle `supabase.auth.signOut()` côté navigateur (même code que la sidebar). Le layout enveloppe tout dans `BackendHealthGuard` (garde de disponibilité du back, non détaillé ici). Pas testé.
